# منصة التحليل — نسخة العميل (مبيعات · مخزون · مشتريات)

نسخة مستقلة من تطبيق التحليل تضم ثلاثة أقسام فقط:

- **إدارة المبيعات**: تحليل المبيعات، البحث عن مبيعات صنف، تحليل الأداء، بيع بلا توريد
- **إدارة المخزون**: تحليل المخزون، حركة فواتير الشراء، مخزون المجموعات، رصيد بلا مبيعات، اختلاف شد الشراء/التحويل
- **إدارة المشتريات**: بحث الأصناف، تحليل المشتريات، دوران الموردين، مقارنات طلب الشراء، طلب النواقص، وشاشات التسعيرة (حد الربح، أصناف غير مسعّرة، أقل من التكلفة، تعديل أسعار اليوم، تسوية التكاليف، اسم مشابه/باركود مختلف، مقارنة أسعار الموردين)

تسجيل الدخول والصفحة الرئيسية مشتركة. لا توجد أقسام مالية أو إدارة مستخدمين في هذه النسخة.

## المتطلبات

- Python 3.12+ (أو Docker)
- اتصال شبكة من سيرفر التطبيق إلى قاعدة **Oracle الخاصة بأونكس ERP** على المنفذ 1521
- **Oracle Instant Client** (إلزامي — مصادقة أونكس تتطلب Thick mode)
  - في Docker يُثبَّت تلقائياً عبر `Dockerfile` — لا حاجة لأي خطوة
  - على Windows: حمّل Instant Client Basic وضع مساره في `ORACLE_CLIENT_LIB_DIR`
- مستخدم Oracle بصلاحية **SELECT فقط** على schema أونكس وعلى `ALL_SYNONYMS`

> التطبيق مبني على جداول أونكس (`IAS_BILL_MST`, `IAS_POS_BILL_MST`, `IAS_POST_DTL` …)
> ويقرأ فقط — لا يكتب أي شيء في قاعدة أونكس.

## التشغيل محلياً

```bash
pip install -r requirements.txt
copy .env.example .env     # إعدادات تقنية فقط — بيانات العميل من شاشة «ربط أوراكل»
python manage.py migrate
python manage.py ensure_app_user
python manage.py runserver 0.0.0.0:8000
```

ثم افتح: http://127.0.0.1:8000/ وسجّل بالحساب المعرّف في `APP_LOGIN_USERNAME`/`APP_LOGIN_PASSWORD`.

## Docker

```bash
docker compose up --build -d
```

## بيانات العميل — من شاشة «ربط أوراكل» لا من الملفات

الشاشة (`/settings/oracle/`، لمدير النظام) هي المصدر **الوحيد** لبيانات العميل — لا تُقرأ من `.env` ولا من الكود.
يُدخل المدير بيانات الاتصال فقط ثم يضغط «اتصال وجلب البيانات»، فيجلب البرنامج الباقي من قاعدة العميل:

| تُدخل يدوياً | تُجلب تلقائياً بعد «اتصال وجلب» |
|--------------|--------------------------------|
| الخادم، المنفذ، اسم الخدمة أو SID | السنوات والوحدات المحاسبية الموجودة (مثل `IAS20261`) — تُختار أحدث سنة |
| المستخدم وكلمة المرور (تُحفظ مشفّرة) | قائمة المخازن النشطة بأسمائها وفروعها — لاختيار المخزن الافتراضي ومخازن المقارنة |
| | رابط خدمة أونكس إن كانت على نفس الخادم (`http://الخادم:8090/Service/OnyxService.svc`) |

ثم «حفظ وتفعيل» — يُختبر الاتصال قبل الحفظ. مفتاح «تفعيل القراءة من أوراكل» يحدد مصدر الكميات
(مفعّل = أوراكل، متوقف = خدمة أونكس).

يبقى في `.env` التقني فقط: `ORACLE_CLIENT_LIB_DIR` (Windows)، المهلات، الدومين، وحساب الدخول الأول.

## وكيل الربط — بدون فتح منفذ أوراكل في راوتر العميل

إن تعذّر فتح المنفذ 1521 عند العميل (أو كان عنوانه متغيراً)، استخدم وكيل الربط:
جهاز قاعدة أوراكل يفتح اتصال SSH صادراً مشفّراً إلى خادم اللوحة، فيظهر أوراكل داخل الحاوية على
`127.0.0.1:15210` فقط — لا يُكشف للإنترنت، والمفتاح لا يسمح إلا بتمرير هذا المنفذ.

1. Dokploy ← Advanced ← Ports: انشر `2222 → 2222` TCP (وضع **host**) ثم Deploy.
2. شاشة «ربط أوراكل» ← «توليد ملف الربط» ← ينزل `OracleLink.zip` (القالب في مجلد [`الربط/`](الربط/)).
3. على جهاز القاعدة: فك الضغط ← «تشغيل الربط.bat» (يثبّت مهمة تعمل مع الإقلاع وتعيد الاتصال تلقائياً).
4. في الشاشة: «استخدام الوكيل في الاتصال» ← اسم الخدمة والمستخدم وكلمة المرور ← «اتصال وجلب البيانات».

توليد ملف جديد يلغي السابق فوراً، و«إلغاء الربط» يقطع الجهاز.

## تجهيز نسخة لعميل جديد

1. انسخ المشروع **بدون**: `.env`، `data/`، `db.sqlite3`، `.secret_key`، `_backup_*` — فيها بيانات العميل السابق.
2. `copy .env.example .env` وعدّل فقط: `DJANGO_ALLOWED_HOSTS` و`CSRF_TRUSTED_ORIGINS` (دومين العميل)،
   و`APP_LOGIN_USERNAME`/`APP_LOGIN_PASSWORD` (حساب مدير النظام الأول)، و`SYNC_SECRET`.
   اترك `DJANGO_SECRET_KEY` فارغاً ليُولَّد مفتاح خاص بالنسخة في `data/.secret_key`.
3. شغّل التطبيق، سجّل الدخول بحساب المدير، وافتح شاشة «ربط أوراكل»: أدخل بيانات الاتصال،
   اضغط «اتصال وجلب البيانات»، راجع السنة والمخازن، ثم «حفظ وتفعيل».

> لا تغيّر `DJANGO_SECRET_KEY` (أو `ORACLE_CONNECTION_SECRET`) بعد الحفظ من الشاشة:
> كلمة مرور أوراكل مشفّرة بمفتاح مشتق منه، وتغييره يتطلب إعادة إدخالها.

## ملاحظات

- ملفات محلية لا تُنسخ ولا تُرفع: `.env` الحقيقي، `.secret_key`, `db.sqlite3`, `data/`
- قاعدة بيانات التطبيق (سجلّات الدخول/الصلاحيات) تُنشأ تلقائياً في `data/` بصيغة SQLite، أو MySQL عبر `DB_*`
